# Referrals API

This guide covers how referral links are generated, resolved, and tracked, including how organizers can view performance analytics and how referral codes integrate with community, event, and hackathon registrations.

For mobile (React Native) integrations, use the `apiClient.request` and TanStack Query patterns from the [mobile-client-guide.md](./mobile-client-guide.md). Also check [referral-native-mobile.md](../referral-native-mobile.md) for explicit client requirements when cookies are unavailable.

---

## 1. Public Links and Tracking

These endpoints are public and do not require authentication. They are used when a guest clicks a referral link (typically structured as `/r/<code>`) or when the client app captures the code from a URL parameter.

### Validate/Resolve a Code (`GET /referrals/public/resolve/:code`)

- **Usage:** Checks if a referral code is valid and active, returning the destination details.
- **Route Parameters:**
  - `code` (string): The 10-character URL-safe referral code (e.g. `REF_XYZ123`).
- **Returns:**
  ```json
  {
    "entityType": "HACKATHON", // "HACKATHON", "EVENT", "FESTIVAL", or "COMMUNITY"
    "slug": "buildathon-2026",  // The unique slug/handle for the target listing
    "isActive": true
  }
  ```

### Track a Click (`POST /referrals/public/track-click`)

- **Usage:** Logs a landing page click event. Call this as soon as the client opens a page with a referral code in the URL. The backend automatically extracts the caller's IP (via headers like `x-forwarded-for` or req connection) and User-Agent to detect and filter out search engine crawl bots.
- **Request Body:**
  ```json
  {
    "code": "REF_XYZ123",
    "source": "https://twitter.com/..." // (Optional) The URL where the referral link was shared
  }
  ```
- **Returns:**
  ```json
  {
    "success": true
  }
  ```

## 2. The Referrer's Dashboard

These endpoints are for the logged-in referrer who is sharing their links. Calls must include Clerk auth headers.

### View Performance (`GET /referrals/my/performance`)

- **Usage:** Returns total statistics and a list of all referral links generated by the current logged-in user.
- **Returns:**
  ```json
  {
    "summary": {
      "linksGenerated": 3,
      "activeLinks": 2,
      "totalImpressions": 150,
      "impressions24h": 10,
      "totalRegistrations": 15,
      "registrations24h": 2
    },
    "referrals": [
      {
        "id": "ref_123",
        "code": "REF_XYZ123",
        "entityType": "HACKATHON",
        "entityId": "hack_123",
        "title": "Buildathon 2026",
        "organization": "OppSkills Core",
        "thumbnail": "https://banner.url/hackathon.png",
        "slug": "buildathon-2026",
        "clicks": 120,
        "clicksLast24h": 8,
        "registrations": 10,
        "registrationsLast24h": 1,
        "createdAt": "2026-06-13T12:00:00.000Z",
        "isActive": true
      }
    ]
  }
  ```

### List Referred Links with Signups (`GET /referrals/my/referred-users`)

- **Usage:** Lists the referral links created by the current user that have generated at least 1 successful signup.
- **Returns:** An array of referral stats objects (matching the schema of the `referrals` array items in the View Performance response).

## 3. Organizer and Admin Tools

These endpoints require Clerk authentication. The caller must be the organizer/owner or a manager of the target listing entity (or a platform administrator).

### List Referrals (`GET /referrals`)

- **Usage:** Retrieves all generated referral links for a specific entity. Used in the organizer dashboard.
- **Query Parameters:**
  - `entityType` (required): `HACKATHON` | `EVENT` | `FESTIVAL` | `COMMUNITY`
  - `entityId` (required): The ID of the target entity.
  - `page` (optional): Page number for pagination (default: `1`).
  - `pageSize` (optional): Items per page (default: `10`, max: `100`).
- **Returns:**
  ```json
  {
    "data": [
      {
        "id": "ref_123",
        "code": "REF_XYZ123",
        "entityType": "HACKATHON",
        "entityId": "hack_123",
        "referrerId": "usr_referrer_123",
        "isActive": true,
        "createdAt": "2026-06-13T12:00:00.000Z",
        "referrer": {
          "id": "usr_referrer_123",
          "firstName": "John",
          "lastName": "Doe",
          "email": "john@example.com",
          "imageUrl": "https://avatar.url/john.png",
          "createdAt": "2026-06-10T12:00:00.000Z",
          "institution": "Stanford University",
          "location": "Palo Alto, California, US",
          "profession": "College Student | Computer Science | 3rd Year",
          "registrationDate": "2026-06-10T12:00:00.000Z"
        },
        "clicksRecent": 10,
        "registrationsRecent": 2
      }
    ],
    "total": 1,
    "page": 1,
    "pageSize": 10
  }
  ```

### Generate a Referral Link (`POST /referrals`)

- **Usage:** Creates a new referral code assigned to a specific user for a specific opportunity.
- **Request Body:**
  ```json
  {
    "entityType": "HACKATHON", // "HACKATHON", "EVENT", "FESTIVAL", or "COMMUNITY"
    "entityId": "hack_123",
    "referrerEmail": "john@example.com", // The existing user who will own this code
    "sendEmail": true // (Optional) If true, emails the generated code and link to the referrer
  }
  ```
- **Returns:** The newly created referral object, including the generated `code` string.
- **React Native Example (TanStack Query):**
  ```typescript
  const createReferral = useMutation({
    mutationFn: (data) =>
      apiClient.request("/referrals", {
        method: "POST",
        body: JSON.stringify(data),
      }),
    onSuccess: () => {
      queryClient.invalidateQueries({ queryKey: ["referrals"] });
    },
  });
  ```

- **Query Parameters:**

  - `entityId` (required): The ID of the target entity.
- **Returns:**

  ```json
    "referredParticipants": 15,
    "totalRegistrations": 15,
    "activeReferrers": 2,

  ```

### Look Up User (`GET /referrals/user-lookup`)

- **Usage:** Confirms that a user exists by their email before generating a referral link for them.
- **Query Parameters:**
  - `email` (required): The exact email address of the user.
  - `entityType` (required): `HACKATHON` | `EVENT` | `FESTIVAL` | `COMMUNITY`
  - `entityId` (required): The ID of the target entity.
- **Returns:**

### Get Referral Details (`GET /referrals/:id`)

- **Usage:** Fetches basic data for a single referral code. Accessible to the referrer and organizers/admins.
- **Route Parameters:**
  - `id` (string): The referral ID.
- **Returns:** Referral details object.

### List Attributed Registrations (`GET /referrals/:id/registrations`)

- **Usage:** Lists the individual users whose registrations were attributed to this referral code. It aggregates signups across different models: Hackathon team leaders, team members, event participants, and community members.
- **Route Parameters:**
  - `id` (string): The referral ID.
- **Query Parameters:**
  - `page` (optional): Page number (default: `1`).
  - `pageSize` (optional): Items per page (default: `10`).
- **Returns:**
  ```json
  {
    "data": [
      {
        "id": "reg_member_123",
        "name": "Alice Smith",
        "email": "alice@example.com",
        "avatarUrl": "https://avatar.url/alice.png",
        "registrationDate": "2026-06-13T14:00:00.000Z",
        "institution": "MIT",
        "location": "Boston, Massachusetts, US",
        "profession": "College Student | EECS | 4th Year"
      }
    ],
    "total": 1,
    "page": 1,
    "pageSize": 10
  }
  ```

### Delete Referral Link (`DELETE /referrals/:id`)

- **Usage:** Soft-deletes a referral link by updating `isDeleted` to `true` and `isActive` to `false`.
- **Route Parameters:**
  - `id` (string): The referral ID.
- **Returns:**
  ```json
  {
    "success": true
  }
  ```

## 4. Module Integrations

When a referral code is used, it must be attributed at the point of registration or community membership creation. Below is how the different modules accept the `referralCode` parameter.

### Community Module

Users can join communities by attributing their join event to a referral.

> [!NOTE]
> If a referral code is successfully validated for a `COMMUNITY` entity type and matches the target community, joining the community creates a `CommunityMemberEntity` with the associated `referralId` and increments the referral's registration count.

- **Endpoint:** `POST /communities/:id/join`
- **Request Parameters:**
  - `id` in route path (Community ID)
- **Request Body:**
  ```json
  {
    "referralCode": "REF_XYZ123" // (Optional) Referral code to attribute
  }
  ```
- **Returns:** The joined member record.

### Event Module

#### Free Events

- **Endpoint:** `POST /events/:id/join`
- **Request Body:**
  ```json
  {
    "referralCode": "REF_XYZ123" // (Optional) Referral code to attribute
  }
  ```

#### Paid Events (Razorpay Flow)

For paid registrations, the referral code must survive redirects and asynchronously trigger on payment callback webhooks.

1. Create Payment Order: Include `referralCode` in the body payload to `POST /events/:slug/payment/order`.
2. Razorpay Order Notes: The backend attaches the `referralCode` to the Razorpay order notes (`notes.referralCode`).
3. Verification / Webhook: Upon verification or receiving the payment webhook payload, the backend resolves the referral ID from the order notes and attributes it to the newly created `EventParticipantEntity`.

### Hackathon Module

#### Free Hackathons

- **Endpoint:** `POST /hackathons/:slug/teams` (Create free team)
- **Request Body DTO fields:**
  ```json
  {
    "name": "Team Alpha",
    "referralCode": "REF_XYZ123",
    "answers": [...]
  }
  ```
- **Endpoint:** `POST /hackathons/:slug/teams/join` (Join free team)
- **Request Body DTO fields:**
  ```json
  {
    "invitationCode": "INV_CODE_ABC",
    "referralCode": "REF_XYZ123",
    "answers": [...]
  }
  ```

#### Paid Hackathons (Razorpay Flow)

- Checkout endpoints `POST /hackathons/:slug/payment/order` and `POST /hackathons/:slug/payment/verify` accept `referralCode` in the DTO.
- It is saved to the Razorpay order notes (`notes.referralCode`) and attributed to the `TeamEntity` (for per-team leader registrations) or `TeamMemberEntity` (for per-member registrations) upon successful webhook payment verification.
