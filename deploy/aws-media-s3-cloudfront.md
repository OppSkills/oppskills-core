# S3 + CloudFront image hosting (Production) — AWS setup checklist

This document describes the **production** AWS resources needed to support **direct browser uploads to S3** (via backend-issued presigned POST) and **public delivery via CloudFront**.

The recommended model is:

- **S3 bucket is private** (Block Public Access ON)
- **CloudFront reads from S3** using **OAC** (Origin Access Control)
- The browser uploads directly to S3 using **presigned POST** generated by the backend
- The app stores and displays the **CloudFront URL** (not the S3 URL)

This is ideal for hackathon banners and other public media. If/when you add private media later (e.g. user profile images), you can either:

- create a separate “private” bucket + CloudFront distribution with signed URLs, or
- keep one bucket but use different prefixes + different CloudFront behaviors.

---

## 0) Decide naming + region

This repo deploys backend infra in **`us-east-1`** (see `deploy/backend-ec2.md`), so this guide assumes:

- **Region**: `us-east-1`
- **Bucket**: `oppskills-assets` (you can rename)
- **Assets domain**: `assets.oppskills.com` (recommended) OR use the default CloudFront domain

---

## 1) Create an S3 bucket (private)

AWS Console → **S3** → Create bucket

- **Bucket name**: `oppskills-assets`
- **Region**: `us-east-1`
- **Block Public Access**: **ON** (all checks enabled)
- **Bucket Versioning**: optional (OFF is fine for now)
- **Default encryption**: **SSE-S3** (AES-256) or SSE-KMS if you already use KMS

### Recommended folder/key layout

Use unique keys so you **never overwrite** existing objects (avoids CloudFront invalidations):

- `public/hackathon-banners/{userId}/{uuid}.{ext}`
- (future) `public/user-profile/{userId}/{uuid}.{ext}`

---

## 2) Configure S3 CORS (for browser uploads)

Because the browser uploads directly to S3, the bucket must allow CORS from your production UI domains.

AWS Console → S3 → Bucket → **Permissions** → **CORS configuration**

Use something like this (replace origins with your real UI domains):

```json
[
  {
    "AllowedOrigins": [
      "https://oppskills.com",
      "https://www.oppskills.com",
      "https://app.oppskills.com"
    ],
    "AllowedMethods": ["POST", "PUT", "HEAD"],
    "AllowedHeaders": ["*"],
    "ExposeHeaders": ["ETag", "x-amz-request-id"],
    "MaxAgeSeconds": 3000
  }
]
```

Notes:

- Presigned POST typically uses **POST**. If you later switch to presigned PUT, keep **PUT**.
- If you use Vercel preview domains, add them too.

---

## 3) Create a CloudFront distribution (S3 origin, OAC)

AWS Console → **CloudFront** → Create distribution

### Origin

- **Origin domain**: select `oppskills-assets` bucket
- **Origin access**: **Origin access control settings (recommended)** → create new **OAC**
  - Signing behavior: **Sign requests**

### Default cache behavior

- Viewer protocol policy: **Redirect HTTP to HTTPS**
- Allowed HTTP methods: **GET, HEAD**
- Cache policy: **CachingOptimized** (fine for images)
- Compress objects automatically: **ON**

### (Optional) Response headers policy

- Add security headers if desired; not required for images.

After creating the distribution, note:

- **Distribution ID**
- **Distribution domain name** (looks like `dxxxxx.cloudfront.net`)

---

## 4) Attach bucket policy to allow CloudFront (OAC) to read objects

CloudFront will show you a button like “Copy policy” / “Update bucket policy”.
If not, set the bucket policy manually:

AWS Console → S3 → Bucket → Permissions → Bucket policy

Replace:

- `YOUR_BUCKET_NAME` with `oppskills-assets`
- `YOUR_CLOUDFRONT_DISTRIBUTION_ARN` with the real ARN:
  `arn:aws:cloudfront::443512646680:distribution/<DIST_ID>`

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "AllowCloudFrontReadViaOAC",
      "Effect": "Allow",
      "Principal": { "Service": "cloudfront.amazonaws.com" },
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::YOUR_BUCKET_NAME/*",
      "Condition": {
        "StringEquals": {
          "AWS:SourceArn": "YOUR_CLOUDFRONT_DISTRIBUTION_ARN"
        }
      }
    }
  ]
}
```

This keeps the bucket private while allowing CloudFront to read.

---

## 5) (Recommended) Add a custom domain for assets (Route53 + ACM)

If you want `assets.oppskills.com`:

### 5.1 Create an ACM certificate (MUST be us-east-1 for CloudFront)

AWS Console → **ACM** → **us-east-1** → Request certificate

- Domain: `assets.oppskills.com`
- Validation: DNS (recommended)

### 5.2 Add domain to CloudFront distribution

CloudFront → Distribution → Settings

- Alternate domain name (CNAME): `assets.oppskills.com`
- Certificate: select the ACM cert you created

### 5.3 Create Route53 record

Route53 hosted zone for `oppskills.com`:

- Record: `assets`
- Type: **A** (Alias)
- Alias target: CloudFront distribution

## 6) IAM permissions (backend signing, chat streaming, optional cleanup)

The backend uses the **EC2 instance IAM role** (`oppskills-ec2-role`) to:

1. **Sign presigned POST** uploads (`s3:PutObject`, …)
2. **Stream chat attachments** from S3 via `GET /chats/.../attachment` (`s3:GetObject` on `private/chat-attachments/*`)

Because you deploy backend on EC2 (see `deploy/backend-ec2.md`), attach this to the instance role (not only a GitHub Actions user).

**Required policy** (bucket name must match):

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "AllowMediaBucketObjectAccess",
      "Effect": "Allow",
      "Action": [
        "s3:GetObject",
        "s3:PutObject",
        "s3:DeleteObject",
        "s3:AbortMultipartUpload",
        "s3:ListBucketMultipartUploads",
        "s3:ListMultipartUploadParts"
      ],
      "Resource": "arn:aws:s3:::oppskills-assets/*"
    }
  ]
}
```

Notes:

- **`s3:GetObject` is required** for chat media/docs. Without it, prod logs show `AccessDenied` on `private/chat-attachments/...` while local dev (broader AWS creds) still works.
- Chat uploads use prefix `private/chat-attachments/`; public hackathon banners use `public/`.
- Legacy objects under `public/chat-attachments/` still need `GetObject` if served through the authenticated attachment endpoint.
- We do **not** use ACLs; public marketing images are still read via CloudFront OAC (bucket policy), not public S3 URLs.

## 7) Production env vars (Secrets Manager)

Backend loads env vars from AWS Secrets Manager secret id `oppskills-env` (see `deploy/backend-ec2.md`).

Add these keys to that secret:

- **`MEDIA_S3_BUCKET`**: `oppskills-assets`
- **`MEDIA_CLOUDFRONT_BASE_URL`**:
  - If using custom domain: `https://assets.oppskills.com`
  - Otherwise: `https://dxxxxx.cloudfront.net`
- **`MEDIA_MAX_UPLOAD_BYTES`**: `10485760` (10 MB)

Optional:

- **`MEDIA_ALLOWED_IMAGE_MIME_TYPES`**: `image/jpeg,image/png,image/webp`

---

## 8) Operational notes

### Cache invalidation

If you use unique keys (recommended), you **do not need invalidations**.

Only invalidate if you overwrite the same key (not recommended).

### Lifecycle rules (optional cost control)

If you plan to upload “temporary” images, add lifecycle rules for a `tmp/` prefix.
For persistent hackathon banners, do **not** expire automatically.

## 9) What we’ll implement in this repo (after AWS setup)

- Backend endpoint: generate **presigned POST** for image upload to S3.
- Frontend: file picker → upload to S3 → save `bannerImageUrl` (CloudFront URL) to the hackathon.
- Enforce:
  - max size **10MB**
  - allowed MIME types (configurable)

## 10) Development setup (recommended)

Goal: make uploads work from `http://localhost:3000` without mixing dev uploads into production.

### Option A (recommended): Separate dev bucket + separate dev CloudFront

Create:

- S3 bucket: `oppskills-assets-dev` (same region `us-east-1`)
- CloudFront distribution pointing to `oppskills-assets-dev` via **OAC**
- (Optional) custom domain `assets-dev.oppskills.com` (ACM in `us-east-1`)

Then:

- **S3 CORS** for dev bucket must include local origins:

```json
[
  {
    "AllowedOrigins": ["http://localhost:3000", "http://127.0.0.1:3000"],
    "AllowedMethods": ["POST", "PUT", "HEAD"],
    "AllowedHeaders": ["*"],
    "ExposeHeaders": ["ETag", "x-amz-request-id"],
    "MaxAgeSeconds": 3000
  }
]
```

### Local backend env (`apps/backend/.env.local`)

Backend reads `.env.local` when `NODE_ENV !== production` (see `apps/backend/src/app.module.ts`).

Set:

- `AWS_REGION=us-east-1`
- `MEDIA_S3_BUCKET=oppskills-assets-dev`
- `MEDIA_CLOUDFRONT_BASE_URL=https://assets-dev.oppskills.com` (or the dev CloudFront domain)
- `MEDIA_MAX_UPLOAD_BYTES=10485760`
- `MEDIA_ALLOWED_IMAGE_MIME_TYPES=image/jpeg,image/png,image/webp`

AWS credentials for local presigning (pick ONE):

- **Preferred**: `aws configure` + `AWS_PROFILE=your-profile`
- Or env vars:
  - `AWS_ACCESS_KEY_ID=...`
  - `AWS_SECRET_ACCESS_KEY=...`
  - (optional) `AWS_SESSION_TOKEN=...`

### Local UI env (`apps/ui-webapp/.env.local`)

Set:

- `NEXT_PUBLIC_API_URL=http://localhost:3001`

### Verify

1. Run backend locally on `http://localhost:3001`
2. Run ui locally on `http://localhost:3000`
3. Click **Upload** on organizer / edit-opportunity banner
4. Network should show:
   - `POST /media/presign-image` → returns `{ uploadUrl, fields, publicUrl }`
   - browser `POST` to S3 `uploadUrl` (201)
   - UI uses the returned `publicUrl` to render the banner

---

## Option B (not recommended): Use prod bucket/CloudFront for local dev

This works technically (just add localhost to the prod bucket CORS and point `MEDIA_S3_BUCKET` / `MEDIA_CLOUDFRONT_BASE_URL` at prod),
but it pollutes production storage with dev uploads. Prefer Option A.
